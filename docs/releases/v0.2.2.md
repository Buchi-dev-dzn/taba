# taba v0.2.2

A backward-compatible patch on v0.2.1. Existing commands, flags, exit codes,
JSON fields and state are unchanged; the additions below are new flags and a
new outcome of an existing status.

- **`taba ps --watch --json`** ([#14](https://github.com/Buchi-dev-dzn/taba/issues/14))
  keeps running and prints the `taba ps --json` document as newline-delimited
  JSON: one compact line at once, then a new full snapshot line only when a
  service's status, port, PID, lease, borrows or claims change, or a service
  is added or removed. It re-reads state every second (`--interval`, at
  least `250ms`), accepts `--scope` and `--running`, and never writes state:
  unlike `ps`, it does not renew the caller's lease. It exits 0 on Ctrl+C
  (SIGINT; on Windows also Ctrl+Break) and when its stdout is closed. An
  error is printed as one `{"ok": false, ...}` line and ends the stream with
  that error's exit status. `--watch` needs `--json` (or
  `TABA_OUTPUT=json`) for now; without it, taba exits with `E_USAGE`. It is
  meant for other programs, such as editors and orchestrators, and is the
  base of the coming `taba ui`. See
  [Watching for changes](../../README.md#watching-for-changes).
- **`taba update` on a version with no GitHub release.** A build of a
  version that was never released (for example `main` after a version bump)
  used to fail with `E_UPDATE_FAILED` (HTTP 404) when `taba update` looked up
  its own release. It now reports `manual_update` with the reason "The
  running version has no matching stable official release." Other failures
  are still `E_UPDATE_FAILED`, and the binary is never touched.
