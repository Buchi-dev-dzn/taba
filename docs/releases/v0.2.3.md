# taba v0.2.3

A backward-compatible patch on v0.2.2: a new command, update progress and a
fix. Existing commands, flags, exit codes, JSON fields and state are
unchanged.

- **`taba ui`** ([#15](https://github.com/Buchi-dev-dzn/taba/issues/15),
  design in [#10](https://github.com/Buchi-dev-dzn/taba/issues/10)), a
  keyboard-driven terminal UI in the same binary, for macOS, Linux and
  Windows terminals. Every scope is a collapsible tree of its services,
  with your scope first and unfolded, refreshed once per second from the
  same code as `taba ps`. `↑` `↓` move, `←` `→` and `Space` fold and unfold
  (view only), `/` filters by scope or service name, `l` follows a log like
  `taba logs -f`, and `q` or `Ctrl+C` quits; quitting never stops anything.
  `x` stops the selected running service, every service of a selected scope,
  or removes an exited service like `taba rm`, after a one-key confirmation
  (`y`). It runs the same code as `taba stop` / `taba rm` as you, never with
  `--force`, so another scope's service or a borrowed one is refused and
  the row shows the CLI's message. The header draws the taba logo in block
  characters with the version and a live summary, in 24-bit or 256 colors.
  Colors stay quiet and follow your terminal theme: the logo's orange only
  in the logo and the `(current)` mark, a green, yellow or gray status dot,
  dim counts and notes, and the selected row as one reverse-video bar
  without colors. `NO_COLOR` or `TERM=dumb` turns colors off. Watching
  changes nothing: the UI never renews
  your lease. Outside an interactive terminal, `taba ui` exits with
  `E_USAGE` and points to `taba ps --watch --json`. See
  [Terminal UI](../../README.md#terminal-ui).
- **`taba ps --watch --json` ends when its reader goes away, even while
  idle.** On macOS and Windows, an idle stream used to keep running after
  its reader closed the pipe (for example `taba ps --watch --json | head -n
  1`) until the next state change. It now notices within a fraction of a
  second on every platform, without writing to the pipe, and exits 0.
- **`taba update` shows its progress**
  ([#22](https://github.com/Buchi-dev-dzn/taba/issues/22)). In a terminal it
  prints on stderr a `#` bar with percent and bytes for each archive it
  downloads (bytes so far when the size is unknown) and a
  `Verifying ... ok` (or `failed`) line per archive. An update downloads
  two archives: the running version's, to prove the installed binary is
  official, and the new one. Nothing extra is printed with `--json`, when
  stderr is not a terminal, or with `TERM=dumb`; stdout, the JSON output and
  `--check` are unchanged. A failed download or Ctrl+C clears the bar line.
  The bar is drawn by the `taba` doing the update, so it first appears when
  updating **from** v0.2.3 to a later release; updating from v0.2.2 to
  v0.2.3 still looks as before.
