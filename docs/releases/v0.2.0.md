# taba v0.2.0

Run local dev servers, watchers and databases outside the agent's terminal,
with explicit ownership and a record of what's running and where.

- **Worktree ownership:** `whoami` resolves a scope; `run --port auto --wait`
  selects a port and waits for readiness. Cross-scope stop and removal require
  an audited override. Taba never stops an unmanaged listener through its CLI.
- **Discovery and scripting:** commands support JSON; `ps --all` lists visible
  TCP listeners without mutating them. `ps --json` now uses a `services` field
  in an object instead of returning a bare array.
- **Agent leases and sharing:** renew or end leases, collect expired services,
  queue a claim, borrow a service instance, or hand it off without restarting.
- **Optional agent hooks:** Claude Code lifecycle hooks and shell checks for
  Claude Code and Codex. Claude Code asks for confirmation on recognized forced
  commands; Codex denies them because its hook does not support `ask`. Hooks
  are best-effort checks, not a sandbox or an authorization boundary.
- **Platforms:** macOS (Apple Silicon and Intel), Windows x86_64, and Linux
  x86_64 and arm64. Windows uses Job Objects and reports the actual stop action
  separately from the stable JSON `signal` field. Windows and WSL hold separate
  process inventories and state.

Existing service records remain readable. Automation consuming the old
`ps --json` array must switch to `.services`; see the [command reference](../../README.md#reference).

See [installation](../../README.md#install) for the GitHub archives, SHA-256
verification, and the source install pinned to `v0.2.0`. No registry package is
part of this release. Linux builds use the GNU ABI and are built on Ubuntu
22.04 (x86_64) and 24.04 (arm64).

For candidate verification, use the `taba-candidate-<commit>` artifact from
[Release candidate](https://github.com/Buchi-dev-dzn/taba/actions/workflows/candidate.yml)
on `main`. It includes all archives, `SHA256SUMS`, and `COMMIT`; verify that
`COMMIT` equals the intended release commit and check every archive against
`SHA256SUMS`. Pull request artifacts exercise packaging but are not release
assets. To rerun packaging while the candidate commit is at the tip of `main`:

```sh
gh workflow run candidate.yml --ref main -f expected_commit=FULL_COMMIT_SHA
```

The workflow can only read repository contents and upload Actions artifacts;
publication is a separate, owner-controlled step.

The automated hook tests replay tool payloads and check that services keep
running. In a disposable Windows workspace, Claude Code reported a successful
SessionStart hook, but the session exited before the `whoami` identity and
SessionEnd could be verified. The bounded Codex smoke attempt timed out under
its existing trust and approval settings; live dispatch is unverified.
