# taba v0.2.1 (draft, unreleased)

A backward-compatible patch on v0.2.0 that adds an explicit update command.
Existing commands, flags, exit codes, JSON fields and state are unchanged.

- **`taba update --check`** reports whether a newer stable SemVer release
  exists on the official `Buchi-dev-dzn/taba` GitHub Releases. It is
  read-only. Drafts and prereleases are ignored.
- **`taba update`** checks the same way. On Linux (x86_64 and arm64) it
  replaces the binary only when the running `taba` is byte-identical to the
  official archive for its own version and passes the ownership, permission
  and location checks. It verifies the new archive against the release's
  `SHA256SUMS` and its expected layout, never runs the downloaded binary,
  and swaps the file with one atomic rename. On failure, the old binary stays
  in place.
- **Manual upgrade elsewhere.** Cargo or source builds, package-manager
  installs, and macOS get a `manual_update` report with the release link. On
  Windows, `taba update` is check-only because taba does not replace its own
  running `.exe`.
- **New error code `E_UPDATE_FAILED`** (exit 1) is used only by
  `taba update`.

taba never checks for updates in the background. `SHA256SUMS` is published
with the archives in the same release, so it detects corrupted or mismatched
downloads but is not an independent signature. See
[Updating](../../README.md#updating).

Before publishing, update the archive names and the pinned tag in
[installation](../../README.md#install) to `v0.2.1`.
