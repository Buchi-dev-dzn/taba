# taba v0.2.6

`v0.2.6` adds project configuration, interactive services and clearer
borrow diagnostics. See the environment and platform behavior changes below.

- **A short form for `taba run`.** `taba run npm run dev` derives the service
  name from the command, waits up to 30 seconds for the port the app listens
  on and reports it. Running the same command again reuses the running
  service, and a derived name that is already taken by another command is
  refused with a `--name` suggestion. A single quoted argument is run as a
  shell command line. If taba options precede an unquoted command without
  `--`, taba reports the corrected command. `taba` with no arguments lists
  services. The explicit form is unchanged, except that its JSON reply now
  includes `discovered_ports`.
- **Project services in `taba.toml`.** `taba up` starts the services declared
  in the nearest `taba.toml`, in file order or the order given, and waits for
  each. It stops at the first failure and leaves started services running.
  `taba down` stops the declared services of your scope. There is no restart
  on crash, health monitoring or dependency graph.
- **`taba run --env` and `--save`.** `--env KEY=VALUE` (repeatable) sets
  environment variables for a service; only names and a keyed fingerprint are
  kept in state. `--save` writes the definition to `taba.toml` so `taba up`
  can start it later. Saved values are plain text in `taba.toml`, so do not
  save secrets. Services no longer inherit the caller's `TABA_AGENT`,
  `TABA_AGENT_PID` or `TABA_OUTPUT`; set them with `--env` if a service
  needs them.
- **Interactive dev servers.** `taba run -i` gives a service a
  pseudo-terminal held by a small holder process, while output still goes to
  the log. `flutter run` and `vite` are interactive by default
  (`--no-interactive` turns this off). Type into a service with `i` in
  `taba logs -f` or `taba ui`, or with `taba attach`. Scripts can use
  `taba send` (text or `--key`), `taba signal` (`USR1`, `USR2`, `HUP`) and
  `taba reload` (Vite dev restart, or Flutter hot reload / `--restart` on
  Linux). `taba ps --json` shows `"interactive": true`.
- **Clearer borrow warnings.** A shared borrow from the service's own scope
  does not protect the service from being stopped or replaced by its owner.
  Taking that borrow now reports `W_SAME_SCOPE_BORROW`.
  `W_BORROW_BROKEN` now names the borrow, the service and the
  `taba release ID` command that cleans it up. In JSON, warnings may carry an
  optional `details` object.

## Platform limitations

- **macOS: no automatic Flutter reload.** `taba reload` and
  `taba reload --restart` return `E_NO_RELOAD` for Flutter on macOS without
  sending a signal. Use `taba attach S/N` and press `r` (hot reload) or `R`
  (hot restart), or run `taba send S/N --key r` / `--key R`. Automatic Flutter
  signalling is available on Linux only, for a verified `flutter run` leader.
- **Windows: no interactive services yet.** There is no ConPTY support yet
  ([#79](https://github.com/Buchi-dev-dzn/taba/issues/79)). `taba run -i`,
  `attach`, `send`, `reload` and `signal` return `E_UNSUPPORTED`, and
  `flutter run` / `vite` start as before, without input. To apply changes,
  restart the service instead of reloading it.
- **Wrappers and older records.** A wrapper that stays as Flutter's process
  leader is not a supported signal target, and Vite preview cannot be
  reloaded (`E_NO_RELOAD`). If such a service has no input, stop it and rerun
  it with `--interactive`.

This release also moves `sha2` to 0.11, pins the third-party GitHub Actions
used by CI and the release candidate workflow to commit SHAs, and adds tests
for garbage-collection timing and `E_SIGNAL_FAILED`.
