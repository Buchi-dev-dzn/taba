# taba v0.2.5

`v0.2.5` is a backward-compatible patch release. Existing commands, flags,
exit codes, JSON fields and the state format remain compatible with v0.2.4.

- **State is safer and more recoverable.** On macOS and Linux, new state
  directories are owner-only (`0700`) and files are owner-only (`0600`); an
  existing state home that the owner can tighten is corrected when opened.
  Writes are flushed before their atomic rename. Empty or unreadable records
  are skipped in listings with `W_STATE_SKIPPED`, are never overwritten, and
  can be removed with the force command named in the error.
- **Contention now has a bounded failure mode.** Commands wait up to
  `TABA_LOCK_TIMEOUT` seconds for the global state lock (10 by default) and
  then return `E_BUSY` with the recorded holder PID when available. `ps` and
  `logs` continue to try only once and do not wait behind a writer.
- **Logs and expiry are easier to inspect.** `taba logs` accepts `--tail N`,
  and JSON log output is capped at 16 KiB with `bytes_total` and `truncated`
  so an unexpectedly large log cannot produce unbounded output. `taba ps`
  now exposes a service that is eligible for lazy expiry as `pending_gc`;
  expiry still does not stop a process until a later cleanup.
- **CLI diagnostics are more useful for scripts.** JSON usage errors identify
  the argument in `details.arguments` and point `next` at the command's help.
  Help text now covers every flag consistently.
- **Linux process identity survives wall-clock changes.** taba keeps a
  boot-time cache beneath its state directory and can recover either cache
  file from its peer during the same boot.

This release also adds coverage for lock contention, damaged state, lease
transitions and the platform-specific paths above.
